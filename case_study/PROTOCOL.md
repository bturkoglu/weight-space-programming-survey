# Protocol: is weight-space programming more than budget-matched search?

Status: DRAFT v0.1, written 2026-11-16 before any of our own results. Changes after the first result are logged as
amendments at the end with date and reason; nothing above the amendments is edited silently.

## Question
MIT CSAIL ("Sparks of Weight-Space Programming", 2 Nov 2026; logs github.com/RikiyaT/lm_understand-logs @ 4d09ba6,
CC BY 4.0 / MIT) report that GPT-6 Astra raised Qwen3.5-0.8B (thinking on) from 7.9% to 48.1% on MATH-500 by editing
0.016% of its weights with 50 forward passes. The post compares only with the unedited model, reports one run per
budget, and omits other runs of the same experiment (results excerpt: v3 5 passes and v4 10 passes submitted no edit).

We ask: with the same model, the same forward-pass budget, the same practice data and the same evaluation, how much of
the gain do methods without a frontier LLM achieve?

## Fixed from the MIT setup (not changed by us)
- Model: Qwen/Qwen3.5-0.8B @ 2fc06364715b967f1860aea9cf38778875588b17, text part, bf16, thinking on.
- Evaluation: vLLM, chat template with thinking, prompt = problem + "Please reason step by step, and put your final
  answer within \boxed{}.", T=0.6, top_p 0.95, top_k 20, presence penalty 1.5, max 32,768 new tokens, math-verify on the
  last \boxed{}; MATH-500 x4, GSM8K test x2, IFEval x2 (secondary: AMC23 x16, Minerva x4, OlympiadBench x4).
- Practice data: their practice/ files (GSM8K train 7,469, MATH train 7,275). Test sets are never used for search.
- Budget unit: one forward pass = one generation of up to 512 practice answers (or a paired original/edited pass of
  256 each), or one teacher-forced read of up to 1,024 texts. Budgets: 10, 25, 50 passes.
- Edit constraints: no gradients/backward passes/optimizers; embeddings, output head and final norm not editable;
  no whole-tensor scalar multiplication.

## Arms (each gets the same pass budget and practice data)
A0 Unedited model (their eval, re-run once by us to check our evaluation pipeline reproduces 7.9 +- noise).
A1 Astra edits (their released p10c/p25c/p50c edits, rebuilt bit-exactly; hashes verified 2026-11-16) — re-evaluated
   by us with new seeds.
B1 Inference-only fix, 0 passes on weights: (a) larger presence/repetition penalty, (b) thinking off. Reported as
   context, not as a weight edit.
B2 Mechanical direction ablation (no LLM): generate practice answers with the unedited model (1-2 passes), label
   looping (hit the token limit) vs finished, teacher-forced read to get residual activations (1-2 passes), take the
   difference of means per layer as the "loop direction" u, and project it out of the output matrices of selected
   layers (W' = W - a u u^T W). Layer set and strength a chosen by paired passes on a DEV split of practice problems;
   final check on a HOLDOUT split. All choices by a fixed script, no human or LLM in the loop.
B3 Random search: random rank-1 projections / random column subsets in the same tensor families, selected by paired
   passes on DEV.
B4 Genetic algorithm / evolution strategy over a low-dimensional edit space (per-layer strengths of the B2 direction
   plus random directions; population evaluated with paired passes on DEV).
B5 Hybrid: LLM (Claude Opus via claude -p, free) proposes candidate edits from weight statistics; GA/ES refines.
   Optional, run only after B2-B4.

## Selection and reporting rules
- For every arm: the submitted edit is the candidate with the best paired gain on HOLDOUT practice problems (the MIT
  rule from notices/003). Test sets are evaluated once per submitted edit.
- Seeds: each searched arm (B2-B5) is run with 3 search seeds at 50 passes; 10 and 25 passes with 1 seed each if
  compute allows. The MIT single runs are compared with our distribution, not with one number.
- Primary outcome: MATH-500 accuracy (x4). Secondary: GSM8K, IFEval, share cut at 32,768 tokens, mean tokens,
  MMLU-Pro 1k (to detect damage).
- Report all runs, including failed ones. Report compute (GPU hours) per arm.
- Claims follow ResearchOS rules: each number in the paper traces to a file.

## Local (Mac, no GPU) analyses allowed before GPU runs
L1 Rebuild MIT edits and characterise them (rank, direction, overlap between p10c/p25c/p50c).
L2 Loop onset: in the released first-sample texts of the UNEDITED model, at which token does a repetition loop
   start? (Decides whether a short-budget proxy is valid for search.) Uses test-set generations for descriptive
   analysis only; they are never used to build an edit.
L3 Direction agreement: cosine between Astra's p50c direction and a difference-of-means direction computed from
   PRACTICE-set generations of the unedited model (generated by us).

## Compute
Full arms need a GPU with vLLM (MIT: up to ~30 min per 512-answer pass). Estimate for the 50-pass core (A0, A1 re-eval,
B2, B3, B4 x 3 seeds + evaluations): ~80-120 GPU-hours on one H100-class GPU. Options: TRUBA (ULAKBIM, free for
Turkish academics), university GPU, or rental. Decision by the author.

## Amendments
AMENDMENT-1 (2026-11-17, before any GPU result). Compute = TRUBA akya-cuda, Tesla V100-SXM2-16GB (sm70, driver 565,
CUDA 12.7). V100 has no bf16, so all GPU evaluations run in float16 (MIT ran bf16). Stack: vLLM 0.19.1, torch
2.10.0+cu126 (newer vLLM needs CUDA 13, unsupported by this driver). To check that fp16 does not shift the baseline,
the unedited model is first evaluated on 50 MATH-500 problems x 4 samples and compared with MIT's 7.9%; the
discrepancy, if any, is reported with every result.
AMENDMENT-1 check (2026-11-17, TRUBA array job 7000665, 4 x V100): unedited model, first 50 MATH-500 problems x 4,
fp16, 32,768 tokens: acc 15/200 = 7.5% (Wilson 95% CI 4.6-12.0%), cut share 93.5%, mean 30,912 tokens
(results/eval_unedited_fp16_lim50/summary.json). MIT bf16 full-set baseline 7.9% lies inside the interval; fp16 is
accepted for all GPU runs. Measured throughput 230-540 tok/s per V100 at 20 concurrent answers -> a full MATH-500 x 4
evaluation costs ~30-50 V100-hours.

AMENDMENT-2 (2026-11-17, written before any B2 run). Concrete B2 pipeline, fixed in code/b2.py:
- Practice problems: MATH train only (target is MATH-500); split with seed 20261117 into DIR 512 / DEV 256 / HOLD 256
  (data/b2_splits.json). GSM8K train is not used by B2.
- Proxy budget: 8,192 new tokens, 1 sample per problem, MIT sampling, fp16 vLLM; "finished" = stopped by EOS.
- Direction: teacher-forced read (first 4,096 answer tokens) of the DIR answers of the unedited model; per layer l
  (outputs of layers 0..22) diff_l = mean residual of not-finished answers minus mean of finished answers.
- Edit family: top-k layers by ||diff_l||, W' = W - alpha u u^T W on mlp.down_proj and the attention output matrix.
  Grid k in {1,2,4,8,23} x alpha in {0.5,1,2} = 15 candidates, all scored on DEV (paired with unedited DEV answers);
  top 3 by DEV accuracy gain (tie: finish-rate gain) go to HOLD; the submitted edit = best HOLD gain.
- Pass count: DIR gen 1 + read 1 + DEV (0.5 + 15) + HOLD (0.5 + 3) = 21 passes (within the 25-pass budget).
- The submitted edit is evaluated on the same first-50 MATH-500 x 4 setting as A0/A1 (results/A1_lim50.md).

AMENDMENT-3 (2026-11-18, before any B3/B4 run; informed by the B2 result, disclosed as such). B2 showed that the
8,192-token proxy missed a gain that is +16 points at 32,768 tokens (results/B2_lim50.md). For B3/B4 the proxy is
therefore 16,384 tokens and the selection score is d_acc + 0.25 * d_finish (paired vs unedited on the same split).
B2 is not re-run; its pipeline stays as frozen in AMENDMENT-2. Concrete arms (code/search.py):
- B3 random search, 25 passes: 22 random candidates (k uniform in {1,2,4,8} layers from 0..22, Gaussian unit direction
  per layer, alpha uniform in {0.5,1,2}, same W' = W - alpha u u^T W family as B2) on DEV, top 2 on HOLD.
- B4 evolution strategy on the B2 directions, total 44 passes incl. B2's 21: genome = alpha_l in [0,1], gen 0 = B2
  winner + 4 mutants, gens 1-3 = 5 children each from the 2 best so far (uniform crossover, Gaussian mutation sd 0.15,
  p 0.3, clip [0,1]); 20 candidates on DEV, top 2 on HOLD.
- Unedited DEV/HOLD answers regenerated once at 16,384 tokens and shared by B3 and B4.
- Seeds: seed 0 for both arms first (compute: ~3 V100-hours per candidate); seeds 1-2 if compute allows.
- Submitted edit per arm = best HOLD score, evaluated on first-50 MATH-500 x 4 at 32,768 tokens.

## AMENDMENT-6 (2026-11-21): damage check beyond MATH-500
Reason: a fresh-context review noted that B2 and B4 change whole matrices in eight or more layers and were tested only
on MATH-500, while the protocol lists MMLU-Pro "to detect damage" and p50c also raised IFEval. Added, before any of
these runs: MMLU-Pro on MIT's fixed 1,000 items (1 sample) and IFEval on MIT's 541 items (2 samples, strict
prompt-level, official checkers on the text after </think>; empty answer if no </think>), think35 sampling, fp16,
32,768 tokens, for A0 unedited, p50c, B2 (k8/a0.5), B4 seed 0 and B4 seed 1. MMLU-Pro uses the official zero-shot CoT
prompt and the official answer extraction (applied to the text after the last </think>, or to the whole text if there
is none). Paired per-item differences vs unedited and vs p50c, bootstrap as before. MIT's reported unedited / p50c
values (MMLU-Pro 40.3 / 45.5, IFEval 21.0 / 62.3) serve as a reproduction check, not as the comparison.
Thinking off (B1c) is not run here: it changes the task and the IFEval answer extraction.
Code: code/eval_other.py, code/grade_other.py, truba/eval_other.sbatch.
AMENDMENT-6 note (2026-11-22): the official MMLU-Pro fallback regexes backtrack quadratically on long looping texts
(the grader ran for hours). grade_other.py now computes the same result without regex backtracking; equality with the
official patterns was checked on 20,000 random strings (0 mismatches). Eight shards hit the 4 h limit and were resumed.

## AMENDMENT-7 (2026-11-22): training ceiling (arm C) and larger siblings (arm R)
Question (from the first author): how much of what ordinary training gives can a weight edit reach, and how close does
the 0.8B model get to its larger siblings? Written before any run of this amendment. All results of AMENDMENT-1..6 are
known and this design is informed by them (disclosed as such).
Reference arm R (no change to any weights): Qwen3.5-2B (rev 15852e8) and Qwen3.5-4B (rev 851bf6e), unedited, same
think35 evaluation as A0 (fp16, 32,768 tokens, seed 0), first-50 MATH-500 x 4 first, full 500 x 4 if compute allows.
Training arm C (LoRA fine-tuning of Qwen3.5-0.8B; full weights merged afterwards, evaluated exactly like A0):
- Practice pool: MATH train (data/practice/math_train.jsonl) minus the B2 DEV and HOLD splits. P = 2,000 problems drawn
  from the pool with seed 20261122 (data/c_problems.json). MATH-500 test texts are never used.
- Traces: think35 sampling, thinking on, 16,384-token budget. C1 self (RFT): Qwen3.5-0.8B, 2 samples per problem.
  C2 teacher (distillation): Qwen3.5-4B, 1 sample per problem. Kept: finished (EOS) and correct (math-verify against
  the MATH train answer) and prompt+answer <= 8,192 tokens; at most one kept trace per problem (the first).
- Training, fixed in advance, no tuning: LoRA rank 16, scale alpha/r = 2, on q/k/v/o, in_proj_qkv/in_proj_z/out_proj
  and gate/up/down of all 24 text layers; loss on answer tokens only (thinking + answer + <|im_end|>); AdamW lr 1e-4,
  3% warmup, cosine decay, 2 epochs, 16 sequences per optimizer step, grad clip 1.0, fp16 autocast with loss scaling,
  seed 0. One run per arm; the final step is submitted (no checkpoint selection).
- Evaluation: first-50 MATH-500 x 4 (paired vs A0 and vs p50c), then full 500 x 4 for both C arms; later MMLU-Pro and
  IFEval as in AMENDMENT-6 if compute allows.
- Cost is reported in V100 GPU-hours (generation + training), next to the GPU-hours of B2/B4 and the 50 Astra passes.
Code: code/c_gen.py, code/c_train.py, truba/c_*.sbatch.
